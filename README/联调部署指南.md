# Cloudflare Tunnel 联调与部署指南

这份指南说明 Qgents 当前的公网访问方式。前端和后端开发都只需要记住两个地址：


| 用途     | 公网地址                           | 本机服务                                |
| ------ | ------------------------------ | ----------------------------------- |
| Web 页面 | `https://qgents.dpdns.org`     | 前端开发服务器 `http://localhost:5173`     |
| API    | `https://api.qgents.dpdns.org` | Spring Boot `http://localhost:8080` |


Cloudflare Tunnel 在运行后端和前端的那台机器上运行，把公网 HTTPS 请求安全转发到本机端口。它不要求路由器开放端口或配置公网 IP。

## 前端同学

### 本地开发

正常启动前端开发服务器。当前 Tunnel 路由指向 `5173` 端口，因此 Vite 默认端口可以直接使用。

前端访问 API 时使用公网 API 地址，不要写死个人电脑 IP：

```text
https://api.qgents.dpdns.org/api/v1
```

建议在前端自己的环境配置中设置：

```properties
VITE_API_BASE_URL=https://api.qgents.dpdns.org/api/v1
```

本地调试仍可使用 `http://localhost:8080/api/v1`。不要把 GitHub Token、Cloudflare Tunnel Token 或后端密钥放进前端环境变量。

### 验证入口

前端服务启动后，打开：

```text
https://qgents.dpdns.org
```

能看到页面表示 Tunnel 已经把公网请求转到了本机前端。若出现 Cloudflare `502`，通常是前端没有启动，或前端实际端口不是 `5173`。

## 后端同学

### 本地环境变量

后端根目录的 `.env` 由 Spring 的 `application.yaml` 自动读取。增加以下非敏感配置，改完后必须重启 Spring Boot：

```properties
CORS_ALLOWED_ORIGINS=https://qgents.dpdns.org,http://localhost:5173,http://127.0.0.1:5173
GITHUB_APP_CALLBACK_URL=https://api.qgents.dpdns.org/api/v1/integrations/github/callback
```

`.env` 不提交 Git。数据库密码、JWT 密钥、GitHub App 私钥路径、Tunnel Token 等敏感值也只能保留在受控环境变量或 Secret 中。

### 验证 API

启动 Spring Boot 后，打开：

```text
https://api.qgents.dpdns.org
```

当前根路径没有业务接口，Spring Boot 返回 `404 Whitelabel Error Page` 是正常现象，说明 HTTPS 和 Tunnel 已通。可继续打开：

```text
https://api.qgents.dpdns.org/swagger-ui/index.html
```

具体业务接口返回 `401` 或 `403` 时，先检查登录态和团队/项目权限；这不表示 Tunnel 出错。

## GitHub App 回调

GitHub App 的回调地址必须填写为：

```text
https://api.qgents.dpdns.org/api/v1/integrations/github/callback
```

GitHub 需要能从公网访问受信任的 HTTPS 地址。没有 Tunnel 时，GitHub 无法访问 `localhost` 或内网 IP；但项目仓库的本地查询、绑定、更新和解绑功能仍可测试。

当前尚未配置完整 GitHub App 凭据时，相关外部调用会返回 `503 GITHUB_APP_NOT_CONFIGURED`，这是预期行为，不应伪造安装或仓库数据。

## 为什么不需要手动做非对称加密

浏览器到 Cloudflare 的连接使用 HTTPS/TLS，Cloudflare 到 Tunnel 也使用受保护的连接。TLS 已经完成了：

- 服务端身份验证：浏览器确认访问的是 `qgents.dpdns.org`。
- 传输加密：登录信息、请求体和响应不会以明文在网络中传输。
- 完整性校验：传输内容被篡改时连接会失败。

因此，前端和后端**不需要自己再写 RSA 加密/解密代码**，也不需要前端保存后端私钥。应用层仍需做登录鉴权、权限校验、密码哈希和 Secret 保护，这些不能被 HTTPS 替代。

GitHub App 的私钥是另一回事：它只用于服务端签名 GitHub App JWT，证明后端是该 App，本质不是给前端请求“再加密一次”。私钥不能传给前端、提交 Git 或写进日志。

## Tunnel 维护

Tunnel 名称为 `qgents-web`，当前一条 Tunnel 承载两个路由：

```text
qgents.dpdns.org       -> http://localhost:5173
api.qgents.dpdns.org   -> http://localhost:8080
```

若迁移到 Docker，路由目标改为 Docker Compose 服务名，而不是 `localhost`：

```text
qgents.dpdns.org       -> http://web:80
api.qgents.dpdns.org   -> http://api:8080
```

Tunnel Token 等同于连接器凭证。不要发送到聊天记录、截图、代码仓库或前端配置；如果泄露，在 Cloudflare 控制台轮换 Token 并更新运行 Tunnel 的机器。

## 常见问题


| 现象                      | 优先检查                                                    |
| ----------------------- | ------------------------------------------------------- |
| Cloudflare `502`        | 本机前端/后端未启动，或 Tunnel 路由端口填错                              |
| Spring `404 Whitelabel` | Tunnel 已通，但请求路径没有对应 Controller；访问 API 根路径时正常            |
| 前端请求被 CORS 拦截           | `.env` 的 `CORS_ALLOWED_ORIGINS` 未包含前端实际来源；修改后未重启后端      |
| 接口返回 `401/403`          | 登录 Token、SecurityContext 用户 UUID、团队/项目成员权限              |
| GitHub 安装或回调返回 `503`    | GitHub App 的环境变量尚未完整配置                                  |
| GitHub 回调访问不到本机         | 回调地址未使用 `https://api.qgents.dpdns.org/...`，或 Tunnel 未健康 |
