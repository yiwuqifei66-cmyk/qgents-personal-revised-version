# 群聊置顶 — 后端接口需求（个人偏好持久化）

> 前端反馈文档 · 供后端实现（2026-08-20）

## 1. 背景

群聊置顶目前是前端 `localStorage` 本地偏好（接口文档注明"会话个人偏好不在本轮范围"），
换设备 / 重新登录后会丢失。需要后端按**用户维度**持久化置顶状态，实现跨设备同步。

## 2. 语义

- 置顶是**个人偏好**：每个用户自己置顶自己关心的群，**不影响其他成员**看到的群列表顺序；
- 不做群公共属性（不要把 `pinned` 写进群表公共字段），存"用户 × 群"的偏好记录。

## 3. 接口设计

### 3.1 群列表返回当前用户的置顶状态

`GET /projects/{projectId}/groups`（现有接口）响应中，每个 Group 增加字段：

```json
{
  "data": [
    {
      "id": "group-uuid",
      "title": "…",
      "type": "REQUIREMENT",
      "pinned": true,
      "…现有字段…"
    }
  ]
}
```

- `pinned`：当前登录用户对该群是否置顶（布尔，默认 false）。
- 若字段缺失/为 null，前端回退到本地偏好（向后兼容）。

### 3.2 设置 / 取消置顶

`PUT /projects/{projectId}/groups/{groupId}/pin`

Body：

```json
{ "pinned": true }
```

- `pinned: true` 置顶，`false` 取消置顶；
- 幂等：重复设置相同值返回 200；
- 权限：项目成员可置顶（只影响自己，服务端校验项目成员身份）；
- 响应：200 + 最新 `{ "pinned": true }`（或 204 无内容，二者选一）。

> 备选 REST 风格：`POST .../pin`（置顶）+ `DELETE .../pin`（取消）。推荐 `PUT + body`，一次请求表达两种状态。

## 4. 存储建议

用户 × 群的偏好表（或 Redis 用户偏好）：

```
user_group_preference
  user_id    UUID
  group_id   UUID
  pinned     boolean
  updated_at timestamp
  主键：(user_id, group_id)
```

- 群被删除/归档时该行可保留（前端按活跃群过滤，不影响展示）；
- 列表接口按 user_id + group_id 反查拼 `pinned`，避免 N+1（一次 IN 查询或 join）。

## 5. 前端配合（后端落地后生效）

- `Group` 类型加 `pinned?: boolean`；
- 置顶按钮：乐观更新（本地立即生效）+ 调 `PUT .../pin`，失败回滚；
- 群列表优先用后端 `pinned`；后端未返回时回退 `localStorage`（当前兜底逻辑，接口未实现期间保持可用）。

## 6. 验证方式

1. 用户 A 置顶需求群 → 群列表该群 `pinned: true`；
2. 用户 A 刷新 / 换设备重新登录 → 置顶状态保持；
3. 用户 B 看同一项目 → 不受 A 置顶影响（B 的 `pinned` 为 false）。
